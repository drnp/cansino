# 00 · 样式与规范指南（所有章节作者必读）

本文档定义《康希诺生物数字化落地方案》全部章节的统一规范。所有写作任务必须遵守。

## A. 标题层级
- 文档总标题（仅最终组装时由 T10 添加）：`# 康希诺生物数字化落地方案`
- 章（chapter）= H2：`## n. 标题`（如 `## 2. 现状盘点：哑铃状格局与四大矛盾`）
- 节（section）= H3：`### n.m 标题`
- 附录：`## 附录A：待核实问题与访谈提纲`（附录A/B/C 由指定任务撰写）

## B. 引用与事实标注规范（强制）
- 康希诺外部核实事实 → `【外部核实·现状核查§4.2】`（节号对应 `.omo/research/cansino-landscape.md` 的章节号）
- 来自原草案的内容 → `【内部材料·原草案§2】`（对应 `intro-draft.md` 的章号，如 §2 现状盘点、§7 风险）
- 行业对标案例 → `【行业对标·对标库§二】`（对应 `industry-benchmarks.md` 的大节号：一~六）
- 无法核实的事实 → 行内 `【待核实】`，并同步收录进 2.7 汇总与附录A
- 禁止：编造系统名、日期、数字；禁止把草案内容伪装成已验证事实

## C. 系统名称规范清单（统一术语，不得另造）
SAP、ERP、OMS、CRM、TMS、MES、SCADA、EMS、BMS、LIMS、QMS、DMS、QRS、WMS、MRP、费控系统、银企直联、采购管理、仓储管理、人力管理、OA协同办公、企业门户、飞书、ESB、数据仓库（数仓）、BI、疫苗追溯（嘉华）
- 首次出现可用「中文说明（英文缩写）」，如「企业服务总线（ESB）」；后续统一用缩写。

## D. 术语锁定
- 数智底座 = 自研统一数字化平台（原草案「自研平台」的新名称，全文统一）
- 存量系统 = 现有 30+ 套业务系统
- 底座应用 = 基于数智底座搭建的轻量化应用
- 目标架构 = 本文档设计的架构；现有架构 = pptx 四层图
- 三条主线 = 强底座 / 补触点 / 提AI（执行摘要核心建议）

## E. Mermaid 白名单（强制）
仅允许：`flowchart`（TB/LR）、`quadrantChart`、`gantt`。
禁止：pie、radar、classDiagram、sequenceDiagram、stateDiagram 等一切其他图型。
节点标签可中文；代码块围栏必须成对；每个内嵌图上方注明来源文件路径（如 `> 源文件：docs/diagrams/01-目标架构总览.mmd`）。

## F. 预算表述规则（强制）
- 任何投资数字必须置于「测算假设」块之后（先列假设：团队规模×人天单价×周期、硬件与云资源、外部咨询）。
- 只允许量级区间（如「千万级」「3,000万–5,000万」）；禁止虚构精确数字（如 3,847.2 万）。
- 技术版本号只作「建议」并加注，不作既成事实。

## G. 管理层语言规则（强制）
- 禁止：代码样例、API Schema、SQL、配置文件片段。
- 多用表格做对比；每章开头 1–2 句点明「对管理层的含义」。
- 技术细节降级为选型理由与风险，不展开实现方案。

## H. 章节字数目标（供控制篇幅）
Ch2≈4,500 / Ch3-4≈6,000 / Ch5≈3,000 / Ch6≈3,500 / Ch7≈1,500 / Ch8≈1,500 / Ch1+9≈2,200 / 附录≈1,000（全文档 15k–25k 字符）
